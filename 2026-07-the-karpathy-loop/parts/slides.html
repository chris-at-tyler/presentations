The Project

autoresearch, in one slide

  • A real LLM training setup, agent-operated. Simplified single-GPU nanochat: the agent modifies the training code, trains 5 minutes, keeps or discards, repeats — overnight.
  • ~12 experiments/hour, ~100 while you sleep. You wake up to a log of experiments and (hopefully) a better model.
  • 21k+ GitHub stars within days of the March 2026 release; forks for macOS, MLX, Windows, AMD within the week.

The premise inversion: "you're not touching any of the Python files like you normally would as a researcher. Instead, you are programming the program.md."

Emphasize it's REAL research infrastructure in miniature, not a toy: Muon+AdamW optimizer, banded attention windows, bits-per-byte eval. Small enough to read in an evening — that's deliberate.
The Anatomy

The whole repo is three files

prepare.py

Fixed. Untouchable.

Data prep, tokenizer, dataloader, the evaluation function. The ground truth the agent cannot game.

train.py

The agent edits this. Only this.

630 lines: full GPT model, optimizer, training loop. Architecture, hyperparameters, batch size — all fair game.

program.md

The human edits this.

The agent's instructions — "essentially a super lightweight skill." Your research org, as markdown.

The division of labor is the design: machines iterate on code, humans iterate on the program that directs the machines.

"Super lightweight skill" is Karpathy's own phrase — the room built skills in part 2; this is the same object running an org of one. Also note what's NOT here: no framework, no orchestrator, no config system.
The Loop

Propose · run · evaluate · keep-or-reset

1 · edit train.pyone experimental idea → 2 · git committhe hypothesis, recorded → 3 · train 5 minuv run train.py > run.log → 4 · grep val_bpbone number decides
improved → advance the branchthe commit stays — knowledge accumulates worse → git reset --hardfailure costs nothing but five minutes

Git is the experiment ledger. The branch's history is exactly the sequence of ideas that worked; discards leave no trace. Plus a results.tsv logging every attempt — keep, discard, and crash alike.

The elegance: no experiment-tracking platform, no MLflow — a branch and a TSV. Crash handling is judgment-based: typo → fix and rerun; fundamentally broken idea → log crash, move on.
Why It Works

Constraints are the science

  • 1One file to modifyscope stays manageable, every diff reviewable in the morning
  • 2Fixed 5-minute budgetevery experiment comparable no matter what changed — model size, batch, architecture
  • 3One metric: val_bpbbits-per-byte is vocab-size-independent, so architectural changes compare fairly
  • 4No new dependenciesthe search space is ideas, not packages
  • 5The simplicity criterion"an improvement of ~0 but much simpler code? Keep." — complexity is a cost the loop actively pays down
Each constraint kills a failure mode: unbounded scope, incomparable runs, metric ambiguity, dependency sprawl, complexity ratchet. Part-2 echo: these are completion criteria and guardrails, engineered.

The Boldest Line

NEVER STOP

"Do NOT pause to ask the human if you should continue… The human might be asleep… You are autonomous. If you run out of ideas, think harder — read papers referenced in the code, re-read the in-scope files for new angles, try combining previous near-misses… The loop runs until the human interrupts you, period." — program.md

Part 2 named the disease: premature completion — agents drift toward "being done." This is the strongest antidote ever written into a skill: the completion criterion is externalized to the human's Ctrl-C.

"Think harder" as an instruction to a machine is the most 2026 sentence in the talk. Note the design honesty: agents naturally stop and check in; overnight autonomy required explicitly engineering AGAINST the default.

Before You Run It

The fine print

  • It runs with permissions disabled. "Spin up your Claude/Codex… and disable all permissions." Overnight autonomy means YOLO mode — run it in a sandbox or dedicated machine, never on a repo you can't afford to surprise you.
  • Tokens are the electricity bill. ~100 experiments a night is ~100 agent sessions. Know your plan's limits before you sleep.
  • Goodhart's law never sleeps either. The agent optimizes the number — exactly the number. The eval harness must be out of reach and correctness must be part of the metric. (Our demo's harness verifies output against a reference for exactly this reason.)
Work-audience credibility slide. The Goodhart point is why prepare.py is read-only and why bench.py checks correctness — an agent WILL find the degenerate optimum if you leave it reachable.

What A Run Looks Like · 1/3
demo/program.md — the adaptation is one substitution
## Experimentation
The goal is simple: get the lowest bench_ms. The harness
verifies your output against a reference implementation
first — correct: False means the run does not count,
no matter how fast it is.

What you CANNOT do:
- Modify bench.py. It is read-only ground truth.
- Add dependencies or import beyond the standard library.

LOOP FOREVER:
2. Change target.py with one experimental idea.
3. git commit
4. Run: python3 bench.py > run.log 2>&1
8. If bench_ms improved (lower), you "advance."
9. If equal or worse, git reset --hard.

NEVER STOP: … The loop runs until the human
interrupts you, period.
Fallback if live stalls. Point out how little changed from Karpathy's original — val_bpb became bench_ms and that's essentially it. The org program is portable; only the experiment swapped.

Four commits — only the ideas that worked. The discard and the crash happened, are logged in results.tsv, and left zero residue in the history. In the morning you review a branch where every diff earned its place.

That's the whole trick: git turns a stochastic search into an append-only record of verified progress.

Morning-after workflow on the real repo: read the kept diffs, read results.tsv for the death toll, cherry-pick or merge. Reviewable diffs was design choice #1 — this slide is why.
Wrap Up · Series Close

Takeaways

  • The loop is a shape, not a repo. One file to edit, one command, one number, git to keep or discard — anything in your world with a number can run it.
  • Autonomy is engineered, not granted. Fixed budgets, untouchable ground truth, correctness in the metric, NEVER STOP — every clause exists because agents drift without it.
  • The human's job moved up a level. You don't write the experiments — you write the program that writes them. Skills (part 2), pipelines (part 3), research orgs (part 4): the same move, three altitudes.
